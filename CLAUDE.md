## Models are code

3D assets are generated by parametric Blender Python scripts, not sculpted by hand and
committed as binaries. When a model needs to change, change the script and regenerate.
Never hand-edit a `.usdz` or check in a `.blend` as the source of truth.

The authoring loop is: edit script → `tools/blender/run.sh` → render a contact sheet →
look at the render → adjust numbers. Always render and inspect before declaring a model
done; the numbers alone do not tell you whether it reads as a fish.

## Shared code lives in Shared/

`Shared/SaverKit` is compiled directly into each saver by `tools/build-saver.sh` — there is
no SwiftPM package, because SwiftPM cannot emit a loadable bundle and the indirection buys
nothing. Anything a second saver would need goes in SaverKit; anything only one saver needs
stays in that saver's `Sources/`.

Same rule for `tools/blender/saverlib`: it holds modeling primitives that any creature or
plant would use. Species-specific numbers belong in the saver's `Models/`.

## Do not generalize on the first use case

Two savers exist before something becomes shared infrastructure. A helper written for one
saver stays in that saver until a second one actually needs it.

## macOS 26 constraints

- Third-party screensavers must use legacy `ScreenSaverView`; the Tahoe engine is private.
- `WKWebView` content blanks after ~3s inside a legacy screensaver. Do not build on WebKit.
- `isPreview` is unreliable on Tahoe. Derive preview-ness from view size, not the flag.
- A loaded bundle is `mmap`ed — `killall legacyScreenSaver` after every install or you will
  debug a stale binary.
- The saver runs sandboxed with no network. Every asset must be inside the bundle.
